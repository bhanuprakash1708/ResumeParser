# AI-Powered Resume Parser (Hackathon Submission)

This project is a high-performance, asynchronous resume parsing API built for the 48-hour AI-Powered Resume Parser Hackathon.

It features a robust backend built with **FastAPI** and a distributed task queue using **Celery** and **Redis**. It ingests multiple document formats (including scanned PDFs via **Tesseract OCR**), extracts raw text, and then uses the **Google Gemini 2.5 Pro** model to intelligently parse that text into a clean, structured JSON format.

The entire system is containerized with **Docker** for one-command setup and deployment.

---

## 🚀 Core Features

* **Asynchronous API:** The `/upload` endpoint is non-blocking. It responds instantly (<1s) by queueing the parsing job, so the user never has to wait for a slow AI call.
* **Background Worker:** A separate Celery worker process handles all the heavy lifting in the background.
* **Multi-Format Ingestion:**
    * ✅ **`.pdf` (Text-based):** `pdfplumber` for fast text extraction.
    * ✅ **`.pdf` (Scanned Image):** `Tesseract OCR` fallback for image-based PDFs.
    * ✅ **`.docx`:** `python-docx` for Word documents.
    * ✅ **`.txt`:** Standard Python file I/O.
* **AI-Powered Extraction (Gemini 2.5 Pro):** Uses the `gemini-2.5-pro` model to analyze the raw text and generate a highly structured JSON object.
* **Guaranteed Structured Output:** Leverages Gemini's "Structured Output" feature (`response_schema`) to *force* the AI to return JSON that perfectly matches the hackathon's required Pydantic schema.
* **Intelligent Analysis:** The AI is prompted to generate the `aiEnhancements` block, providing a `qualityScore`, `completenessScore`, `industryFit`, and `careerProgressionAnalysis`.
* **RESTful API & Documentation:** Full OpenAPI 3.1.x documentation is auto-generated by FastAPI at the `/docs` endpoint.
* **Database Storage:** All results are stored in a **PostgreSQL** database using the `JSONB` type for efficient data handling.

---

## 🛠 Tech Stack & Architecture

A microservice-oriented architecture was chosen to handle the "Performance and Scalability" requirement. The system is composed of four distinct Docker containers.

1.  **`api` (FastAPI, Python)**: The main web server. It handles all HTTP requests, validates input, creates an initial "pending" job in the database, and pushes the job ID to the Redis queue. It also serves the final JSON data.
2.  **`worker` (Celery, Python)**: The "brain." This is a separate process that does one thing: watch for new jobs. It handles all the slow tasks (OCR, calling the Gemini API) so the `api` container stays fast and responsive.
3.  **`redis` (Redis)**: The message broker. It's the high-speed "mailbox" that the `api` uses to send job tickets (like "Parse this file!") to the `worker`.
4.  **`db` (PostgreSQL)**: The persistent database. It stores all file metadata and the final, structured JSON data from the AI.

### 🔄 The Data Flow (Step-by-Step)

1.  A user `POSTS` a file to `/api/v1/resumes/upload`.
2.  The **FastAPI** server receives it, calculates a unique hash (to check for duplicates), and saves the file to a shared `/uploads` folder.
3.  It writes a new row to the **PostgreSQL** database with `status: "pending"`.
4.  It immediately sends a tiny message to **Redis**: `{"task": "parse_resume", "resume_id": "..."}`.
5.  The API returns a `200 OK` to the user in **~50 milliseconds**.
6.  ---
7.  A few moments later, the **Celery Worker** (which is always listening to Redis) sees the new job and picks it up.
8.  It finds the record in the database and updates its status to `"processing"`.
9.  It runs the file through the parsing pipeline (`pdfplumber`, then `tesseract` OCR if needed) to get raw text.
10. It sends this text to the **Gemini 2.5 Pro API**, *explicitly* telling it to return JSON that matches an `AI_ParsedData` Pydantic schema.
11. The AI does the extraction *and* the `aiEnhancements` analysis, returning a single, clean JSON blob.
12. The worker saves this JSON to the `structured_data` column in the database and sets the status to `"completed"`.
13. Now, when the user calls `GET /resumes/{id}`, they get the complete, structured JSON.

## 🏁 How to Run This Project

### Prerequisites

* **Git**
* **Docker Desktop** (Must be open and running)

### 1. Clone the Repository

```bash
git clone [https://github.com/gouravez/ai-resume-parser.git](https://github.com/gouravez/ai-resume-parser.git)
cd ai-resume-parser

2. Set Up Your Environment File
```
A Google Gemini API key is required to run this project.

Copy the example file:

Bash

cp .env.example .env
(On Windows CMD, use copy .env.example .env)

Open the .env file and paste your API key:

Ini, TOML

# ... (other database settings) ...

# --- AI Model API Keys ---
GEMINI_API_KEY="AIzaSy...your...key...here"
3. Run the Application
This 3-step process ensures a clean build that installs all system dependencies (like Tesseract) and creates the database with the latest schema.

Step 1: Stop and Delete Old Data (This clears any old database volumes to apply new table changes)

Bash

docker compose -f docker/docker-compose.yml down -v
Step 2: Force a Fresh Rebuild (This will take a few minutes as it installs Tesseract and all Python packages)

Bash

docker compose -f docker/docker-compose.yml build --no-cache
Step 3: Start the Application (This launches all four containers: api, worker, db, and redis)

Bash

docker compose -f docker/docker-compose.yml up
4. You're Live!
Your terminal will show logs from all four services. Once the api and worker logs show --- Gemini Pro model configured successfully (with Structured Output) ---, the system is ready.

You can now access the interactive API documentation: http://localhost:8000/docs
